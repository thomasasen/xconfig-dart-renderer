# V1.4.0 – Flight reconstruction and per-preset visual QA

## Problem addressed

V1.3.3 fixed shaft/root continuity, but the source-vs-builder review exposed a separate flight problem: for several presets the alpha silhouette of an already photographed flight was also used as the 3D fin geometry. That couples source-camera perspective to the later renderer projection and can create a visual double-perspective effect.

## V1.4 contract

The renderer now separates four concerns:

1. **Flight artwork** – source-grounded visible pixels where available.
2. **Canonical flight geometry** – No.2, No.6, Standard or Vapor-S-like fin profile, independent of the photographed pose.
3. **Source comparison pose** – an explicitly HEURISTIC QA pose used only to make the product-source comparison meaningful.
4. **Board pose** – incidence/roll applied by the renderer and kept independent from the product image.

Every rendered flight/rear definition now exposes:

- `planeProfile`
- `planeProfileProvenance = CANONICAL-GEOMETRY-NOT-PHOTOGRAPHED-POSE`
- `planeUvEnvelope`
- `planeATexture`
- `planeBTexture`

The UV envelope fits visible source artwork to canonical geometry without reusing the photographed silhouette as physical 3D geometry.

## Provenance rules

- Plane A stays SOURCE-GROUNDED where original pixels actually exist.
- De-occluded source-hidden strips remain explicitly approximated.
- Plane B remains APPROXIMATED unless independently verified.
- Web-referenced reconstructions remain HEURISTIC and are not promoted to source-grounded.
- The source comparison pose is HEURISTIC-SOURCE-MATCH and is not a claim about the real dart's board pose.

## Per-preset QA

Browser QA generates one `runtime-<preset>-source-vs-render.png` panel for **every preset**.

Each panel contains:

1. the persisted comparison source,
2. the builder at the source-match QA pose,
3. the normal posed runtime output.

The automated suite also hard-checks:

- exact tip anchor `(0,212)`,
- no second flat-perspective stage,
- canonical flight geometry provenance,
- vertically balanced fin geometry,
- valid monotonic UV envelope,
- comparison source availability,
- source-comparison incidence = 0°,
- barrel/rear and shaft/root continuity,
- WebGL lifecycle/context restore,
- all renderer self-tests.

## Interpretation

A green automated run is necessary but not sufficient for final visual acceptance. The generated per-preset panels must also be manually inspected for:

- overall flight silhouette,
- flight/root proportion,
- duplicated cross-fin artifacts,
- logo/text distortion or mirroring,
- texture-to-fin alignment,
- source-vs-builder scale,
- implausible fin dominance,
- rear continuity.

Where the repository only contains a reconstruction rather than original source pixels, QA can validate internal consistency against that reconstruction but cannot claim product-photo fidelity.
